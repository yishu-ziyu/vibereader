# VibeReader Knowledge Workbench 产品愿景

更新时间：2026-07-01

## 1. 产品定义

VibeReader Knowledge Workbench 是一个以阅读为入口的本地知识飞轮。

用户不是为了“和 PDF 聊天”而来，而是为了在真实阅读中保持注意力、理解结构、保留证据、沉淀知识，并在未来继续复用这些知识。

核心表达：

> 你读过的每一份材料、保留的每一条笔记、生成的每一张卡片，都会变成可追问、可引用、可回到原文的个人知识库。

## 2. 为什么不是普通 ChatPDF

普通 ChatPDF 的默认心智是：

```text
上传文件 -> 问问题 -> 得到答案 -> 结束
```

我们的默认心智应该是：

```text
打开材料 -> 进入阅读 -> 维持注意力 -> 追问理解 -> 保存证据 -> 沉淀知识 -> 未来复用
```

差异不在于“有没有大模型”，而在于用户完成阅读后是否变得更强：

- 用户更知道自己读到了什么。
- 用户更容易回到证据。
- 用户更容易复用自己的理解。
- 用户的知识库随着每次阅读变得更有价值。

## 3. Reader 与 RAG 的产品关系

VibeReader 是阅读入口。

它负责：

- 文档打开与阅读体验。
- PDF 页码、段落、选区、高亮。
- 滑词、笔记、卡片、任务。
- 右侧 AI 工作台。
- 用户注意力和阅读节奏。

UniRAG 是长期知识记忆。

它负责：

- 文档解析。
- chunk 与索引。
- 本地检索、rerank、引用式回答。
- 知识库隔离。
- 多源导入。
- 将用户确认有价值的内容变成后续可检索资产。

二者合起来不是两个工具拼接，而是一个闭环：

```text
阅读现场 -> 用户确认 -> 知识沉淀 -> 后续追问 -> 回到证据 -> 新一轮阅读
```

## 4. 目标用户

第一批用户就是我们自己。

具体画像：

- 读 AI 报告、论文、产品文档、技术规范的人。
- 需要长期积累知识，而不是一次性总结的人。
- 需要引用可靠、能回到原文的人。
- 愿意使用自己的模型服务和本地工具链的人。
- 对隐私、可控性、文件留档有要求的人。

后续可扩展用户：

- 研究生、博士生、科研工作者。
- AI 产品经理、投资研究员、咨询分析师。
- 知识工作团队。
- 需要本地私有知识库的组织。

## 5. 产品原则

### 5.1 Reader-first

第一屏应该让用户进入阅读，而不是进入配置、聊天或资料库管理。

AI 是阅读能力增强，不是喧宾夺主的主角。

### 5.2 Evidence-first

重要回答必须能追溯到来源。

引用失败时必须诚实降级：

- 精确页码可用，就跳页。
- 段落可用，就跳段落。
- 只有来源可用，就展示来源但不假装精确。
- 没有证据，就不能包装成可靠结论。

### 5.3 User-confirmed memory

长期记忆不应该把所有 AI 输出都无差别塞进知识库。

优先进入长期知识库的内容：

- 用户高亮。
- 用户笔记。
- 用户保存的卡片。
- 用户确认保留的 AI 解释。
- 用户反复追问形成的主题线索。

### 5.4 Local-first

默认本地运行、本地存储。

远程模型调用必须是用户主动配置后的行为。模型 key、用户文档、私人笔记不能进入 git。

### 5.5 Model-flexible

我们第一批用户只能依赖自己真实拥有的模型服务。

模型能力必须通过 Adapter 接入，不能把产品绑定到某一个供应商、某一种请求格式或某一个过时模型名。

### 5.6 Flywheel-first

核心价值不是单次问答，而是复用。

每次阅读都应该让未来的阅读变轻：

- 读过的材料能再次被问到。
- 保存的笔记能成为答案证据。
- 卡片能被复习、重组、再解释。
- 知识库能跨文档形成主题线索。

## 6. 核心体验闭环

### 6.1 第一次阅读

1. 用户打开 PDF。
2. Reader 立即显示内容，不等待 RAG 完成。
3. 后台开始索引。
4. 用户滑词、提问、保存笔记。
5. AI 回答带引用。
6. 用户点击引用回到原文。

### 6.2 第二次复用

1. 用户打开新材料。
2. 系统知道旧笔记和旧卡片。
3. 用户提问时，答案可以同时引用当前材料和过去沉淀。
4. 用户继续保存新的理解。

### 6.3 长期飞轮

1. 用户积累多个主题。
2. 知识库开始形成跨文档线索。
3. 用户可以围绕主题追问。
4. 系统始终保留证据链。

## 7. 第一阶段成败标准

第一阶段不是看功能多不多，而是看闭环是否成立。

必须成立：

- 打开 PDF 后能正常阅读。
- 能把当前文档送入 UniRAG。
- 能问一个问题并拿到答案。
- 答案能显示引用。
- 引用至少能回到页码级来源。
- 用户能把有价值内容保存为笔记或卡片。
- UniRAG 失败时 Reader 不崩溃，有 fallback。

暂时不要求：

- 完美知识图谱。
- 多用户协作。
- 云同步。
- 完整桌面打包。
- 精准到字符级 citation。

## 8. 产品命名暂定

内部项目名：

- VibeReader Knowledge Workbench

用户侧可以继续保留：

- VibeReader

原因：

- 用户第一感知是 Reader。
- UniRAG 更适合作为背后的 Knowledge Module。
- 不宜让用户觉得自己在操作两个产品。

## 9. 长期方向

长期产品不是“读文档工具”，而是个人知识操作系统的一部分。

演进路径：

1. Reader：读得进去。
2. Grounded AI：问得可靠。
3. Notes/Cards：留得下来。
4. RAG Memory：找得回来。
5. Knowledge Library：组织得起来。
6. Agentic Workflow：能围绕知识执行任务。
